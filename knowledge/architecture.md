# Hosting model

The site is a static Astro build served by GitHub Pages at the root of `https://sina-shiri.com` from the public repository `sinashiry/sinashiry.github.io`. There is no server runtime, database, form backend or analytics. Astro has no `base`; every URL is root-absolute and the canonical host is hard-coded in the layout and sitemaps.[^astro]

`.github/workflows/pages.yml` runs on every push to `main` and on manual dispatch. It installs build dependencies with `npm ci --omit=dev --ignore-scripts`, runs `npm run check`, `npm test` and `npm run build`, and uploads only `dist/` with `actions/upload-pages-artifact`; the deploy job runs only for `main`. The workflow needs no repository secrets. One concurrency group per ref keeps `main` deploys serialised, so a build-only run on another branch cannot cancel a pending deploy. A failed check, test or build leaves the live site unchanged.[^deploy]

# Content flow

`content/` → `scripts/compose-content.mjs` → generated `src/data/content.json` → `astro build` → `scripts/prepare-pages.mjs` → `dist/` → `actions/upload-pages-artifact` → `actions/deploy-pages`.[^compose][^prepare]

- Compose merges `content/cms/*.json` into the locked structure and enforces every field rule from `content/contract.json`, reporting errors by editor path (for example `Engineering projects › Fire & smoke vision › Approach`). `npm run check` validates without writing and also fails when `.pages.yml` is stale.
- `.pages.yml` is generated by `npm run pages-config` from the structure, contract and labels; never edit it by hand.[^cms]
- Shape changes (a new field, project, list item, route or asset) follow the reviewed procedure in the header of `scripts/split-content.mjs`, then regenerate `.pages.yml` and keep `npm run compose` byte-stable.[^split]
- Routing and asset fields (project slugs, image paths, categories) are locked. The owner edits text in place but cannot add, remove or reorder list entries.

# Pages CMS editing and the public repository

The owner signs in to Pages CMS with the `sinashiry` GitHub account. The Pages CMS GitHub app should be installed for this repository only; it commits directly to `main`, so every save starts a deploy. `/admin/` is a `noindex` entrance page that links to Pages CMS and the Actions tab and grants no access itself. GitHub and Pages CMS decide who may edit. `docs/EDITOR.md` is the owner's guide.

**The repository is public.** Everything saved in Pages CMS is public in Git history the moment it is saved: draft posts, unapproved recommendations, referee names and email fields, academic-profile slots and every upload, including superseded CV versions. Removing something later does not remove it from history. The build still omits empty or unapproved slots from the HTML, but that is a presentation rule, not confidentiality. Save only what may be public.

Pages CMS media folders: article and paper images in `public/assets/owner-media/` (random file names), paper PDFs in `public/assets/owner-media/papers/`, and CV versions in `content/uploads/cv/`. Uploads are public immediately.

# CVs

CV PDFs are uploaded to `content/uploads/cv/` and selected in `content/cms/downloads.json`. The build checks each selected file (path inside that folder, not a symlink, 12 bytes to 12 MiB, `%PDF-` header and `%%EOF` trailer) and copies it to `/downloads/Sina_Shiri_Engineering_CV.pdf`, `/downloads/Sina_Shiri_Masters_CV.pdf` and the legacy `/wp-content/uploads/2022/12/Sina-Shiri-CV.pdf`. `public/downloads/` keeps only the LaTeX sources, which are separate artifacts: changing a PDF does not update its LaTeX source. `astro dev` does not serve the PDFs.[^prepare]

# Post-build step

`scripts/prepare-pages.mjs` rewrites only the build output:[^prepare][^transforms]

- **Private slots:** removes empty optional, recommendation, academic-profile, reference and link markup with balanced wrapper removal, and omits whole groups that have no ready entry.[^visibility]
- **Repository data:** writes the schema-2 `/data/github-repositories.json` projection.
- **Legacy URLs:** writes 15 static stubs for WordPress URLs whose path changed (meta refresh, canonical, `noindex`, `location.replace`) and injects a query hook into `index.html` and `404.html` that maps `?p=`, `?page_id=` and `?attachment_id=` to current pages. Retired WordPress URLs return the ordinary 404 page; Pages cannot send 301 or 410 responses.[^legacy]
- **Security metas:** adds a per-page `Content-Security-Policy` meta with SHA-256 hashes of the final inline scripts, and a `strict-origin-when-cross-origin` referrer meta, before any script. `frame-ancestors`, HSTS, X-Frame-Options, nosniff, Permissions-Policy and custom cache headers cannot be set from a static Pages site and are not provided.
- **Collection visibility:** checks that navigation and robots tags agree with `sitemap-collections.xml`.
- **Deploy guards:** the build fails on retired-backend markers or workstation paths in generated files and executable markup; on words from an optional, git-ignored maintainer list (`.private/guard-words.txt`, skipped when absent); on dotfiles (an empty Pages CMS `.gitkeep` is dropped first), symlinks and server or data file types; on third-party assets in resource-loading tags, styles or CSS; on any file over 95 MiB or a site over 900 MiB; and on missing required files. HTML pages carry owner prose and code samples, so apart from the always-forbidden markers only maintainer markup (inline scripts, styles and same-origin URL attributes) is searched there. A small tag walker that consumes quoted attribute values drives both the CSP hashing and these guards.

`astro.config.mjs` keeps the shared site script external and cacheable; other small scripts are inlined and hashed into the policy.

# Blog and publications

Posts are `src/content/blog/<slug>.md` (YAML front matter plus Markdown) and papers `src/content/papers/<year>-<title>.json`. The file name is the permanent slug: Pages CMS disables renaming for both collections and deleting for posts, and archiving keeps a slug reserved.[^collections]

- **Visibility:** each entry is `draft`, `published` or `archived`; only `published` entries render, on the next deploy. Content rules (media, links, DOI, year, related project, image description, an article length of 60,000 characters) are errors for published entries and warnings otherwise, so an unfinished draft never blocks a deploy.
- **Rendering:** a minimal escaped Markdown subset (paragraphs, headings, lists, code, bold, validated HTTPS links and reviewed images with meaningful alternative text). Raw HTML is never passed through.
- **Thresholds:** Blog navigation and indexing need 3 published posts; Publications needs 1 published paper. Below a threshold the index page is `noindex,follow` and left out of `sitemap-collections.xml`, while published article URLs are always listed. `Base.astro` hides the navigation links with `data-collection-nav` and `hidden`.
- **Papers** support abstract, citation, PDF, related project, featured flag, optional personal contribution and an optional HTTPS code link. Preprints are never grouped as peer-reviewed work.

# GitHub directory

`/code/` renders `src/data/github-repositories.json` as a dated static snapshot. The browser may refresh it from the same-origin `/data/github-repositories.json`; visitors never call GitHub. Public descriptions, purpose labels and related-case links come only from the reviewed `src/data/repository-overrides.json`, keyed by immutable repository ID. Unreviewed repositories get neutral copy, and raw GitHub descriptions are never used as public copy.[^repository-review]

`.github/workflows/github-repositories.yml` runs `scripts/sync-github.mjs` every 6 hours, on manual dispatch and from the Pages CMS "Refresh GitHub repositories" action. It reads only fixed public API endpoints for `sinashiry` within request, size and time budgets, validates the complete list and the reviews, and commits the snapshot only when repository data changed or as a weekly heartbeat that keeps the schedule active. Pushes made with `GITHUB_TOKEN` do not trigger workflows, so it then dispatches `pages.yml`.[^sync]

**Loop guard:** the site repository itself (ID `1414720350`) is listed with a reviewed entry, but its timestamps, size and language data are ignored, so the site's own commits never cause another snapshot commit.

# Contact, privacy and media

Contact is email only: a "Write to Sina" section with a `mailto:` button and four topic cards with subject lines, the contact cards and a copy-email button. Other pages link to `/contact/#write-to-sina`. The privacy page states that there are no analytics, cookies or third-party scripts, and explains GitHub Pages' own request logging.

`/gallery/` derives its catalogue from the project galleries and videos, deduplicates by source URL and keeps every project association; AI concept images are labelled separately from photographs. Thumbnails in `public/assets/gallery-thumbs/` and `src/data/media-thumbnails.json` are generated by `scripts/prepare-media-thumbnails.py` (Pillow, a maintainer-only dependency). Videos are silent, privacy-edited copies and play only on request; without JavaScript every media link still opens the file.

# Identity

`public/assets/sina-shiri-mark.svg` is a native S built entirely from three parallel charcoal PCB traces on a mint tile. Each trace follows the complete S with constant offsets, 45-degree bends and integrated terminal vias; there is no filled letter or separate decorative branch. It is mirrored to `public/favicon.svg` and rendered by `Base.astro` in the header and footer. References carry `?v=trace-s-3` for cache busting; change the version when the artwork changes. The decorative mark has empty alternative text beside the visible name.[^base]
