# Maintainer instructions

Start with [README.md](README.md), then the [knowledge index](knowledge/index.md). Read the relevant architecture or operations concept before changing a shared contract. This file applies to the whole repository; direct user instructions take precedence.

## Scope and modules

- The site is a static Astro build deployed to GitHub Pages and edited through Pages CMS ([architecture](knowledge/architecture.md)). There is no server runtime, database, form backend or analytics; do not add one.
- Keep changes in the owning module: markup in `src/components` and `src/pages`, behaviour in `src/scripts`, shared styles in `src/styles`, collection rules in `src/lib`, build, sync and verification in `scripts`, and workflows in `.github/workflows`.
- Keep every URL root-absolute (no Astro `base`) and the canonical host `https://sina-shiri.com`.
- Do not add third-party forms, analytics, fonts, CDNs, embeds or trackers. The CSP meta and the deploy guards reject third-party assets.

## Content

- Editable text lives in `content/cms/`. The shape and locked values live in `content/structure.json`, field rules in `content/contract.json`, and editor labels in `content/labels.json`.
- `src/data/content.json` is generated by `npm run compose` and git-ignored. Never hand-edit it or `.pages.yml`; regenerate `.pages.yml` with `npm run pages-config`.
- Shape changes (new fields, projects, list items, routes or assets) follow the steps in the header of `scripts/split-content.mjs`. Keep `npm run compose` byte-stable, and do not make routing or asset fields editable.
- Blog posts are `src/content/blog/<slug>.md` and papers `src/content/papers/*.json`. The file name is the permanent slug; never rename or delete a published entry, archive it instead.
- Thresholds are fixed: Blog needs 3 published posts and Publications needs 1 published paper. Below them the index is `noindex,follow` and excluded from `sitemap-collections.xml`, while published article URLs stay listed.
- CV PDFs are uploaded to `content/uploads/cv/` and selected in `content/cms/downloads.json`. The LaTeX sources in `public/downloads/` are separate and are not updated by a PDF change.
- GitHub directory copy comes only from the reviewed `src/data/repository-overrides.json`, keyed by repository ID. Keep the sync workflow's loop guard for the site repository (ID `1414720350`).

## The repository is public

- Everything committed, including every Pages CMS save, is public in Git history immediately: drafts, unapproved recommendations, referee slots, uploads and superseded CVs. Hiding an entry from the HTML does not make it private.
- Never commit credentials, tokens, private configuration, personal contact data beyond the published address, visitor data, raw source media, archives or workstation paths. `.gitignore` is a guardrail, not a secret scanner.
- Workflows use only `GITHUB_TOKEN` with the permissions they declare; do not add repository secrets.

## Evidence and editorial rules

- Public claims come from reviewed content, source evidence and explicit owner corrections. Never invent ranks, certifications, affiliations, measurements, research results, papers, publication acceptance, recommendation text, referees or profile links.
- IstaSanat employment is 2017–present. Describe the current freelance hardware-security research only with details the owner supplies; never add an affiliation, method or result.
- Preserve collaborator credit, sourced co-authorship and original GPA scales.
- Keep trading material out of the curated CV and project narrative. The separate GitHub directory lists every public repository at the owner's request, including unrelated repositories, forks and archives, labelled honestly.
- Recommendations must be authentic and approved for publication. A card needs `approved = yes` plus a quote, name and professional status. References need approval plus name, role and relationship. Academic profiles need a label and an HTTPS link. Incomplete entries are removed from the HTML, and empty groups are omitted entirely. Current research needs both a question and a contribution.
- `measuredOutcome` and `referenceUrl` are filled only from supplied evidence, never inferred.
- Homepage covers and the aerial concept image are AI illustrations. Keep them labelled, and keep real photographs, diagrams and videos on the case-study pages. Preserve privacy edits and silent video copies.
- The identity mark is the three-trace PCB "S" described in [architecture](knowledge/architecture.md#identity). Bump its `?v=` cache key whenever the artwork changes.
- Refer to Sina by name, not with gendered pronouns.

## Validation and release

- Run `npm run check`, `npm test`, `npm run build` and `npm run smoke` before merging. CI runs check, test and build before every deploy.
- For UI changes, also check keyboard use, narrow screens, reduced motion, no-JavaScript content, native media controls and print output.
- Release means merging to `main`; rollback means `git revert` on `main`. Never force-push `main`, because Pages CMS and the sync workflow also commit to it.
- Report local validation, deployment and live verification as separate states. Do not mark anything deployed without a live readback.
